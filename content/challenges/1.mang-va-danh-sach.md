## Giới thiệu

Mảng động là một vùng nhớ liên tục, nhưng luôn có sẵn vài ô trống để dành cho phần tử mới. Khi các ô trống hết, chương trình sẽ xin một vùng nhớ lớn hơn (thường gấp đôi) rồi chép dữ liệu sang đó. Trong bài này, mục tiêu duy nhất là bạn tự tay cài đặt một Dynamic Array.

## Kiến thức cần nhớ

### Size và capacity

Hai khái niệm này rất dễ nhầm, nên hãy phân biệt rõ:

- `size`: số phần tử bạn đang thực sự dùng.
- `capacity`: số ô đã được cấp phát sẵn trong bộ nhớ.
- Khi `size == capacity` mà bạn vẫn `push`, mảng buộc phải cấp phát lại một vùng lớn hơn.

### Vì sao phải nhân đôi?

Khi hết chỗ, ta cấp một vùng mới gấp đôi, chép toàn bộ dữ liệu sang, rồi mới thêm phần tử mới. Vì luôn để dư chỗ như vậy, lần cấp phát lại tiếp theo sẽ còn lâu mới xảy ra. Nhờ thế, tính trung bình trên nhiều lần `push`, mỗi lần chỉ tốn $O(1)$.

### Bảng độ phức tạp

| Thao tác | Độ phức tạp | Lý do |
| --- | --- | --- |
| `get/set` theo chỉ số | $O(1)$ | Tính thẳng được địa chỉ của ô cần dùng |
| `push/pop` ở cuối | $O(1)$ trung bình | Thỉnh thoảng phải chép lại khi mảng đầy |
| `insert/erase` ở giữa | $O(n)$ | Phải dồn các phần tử phía sau để giữ mảng liền nhau |
| `reserve/shrink` | $O(n)$ | Cấp vùng mới rồi chép dữ liệu một lần |

### Khung struct

```c
// C
typedef struct {
  int *data;
  size_t size;
  size_t capacity;
} DynamicArray;
```

```cpp
// C++: class DynamicArray với data_, size_, capacity_ + destructor
```

Các quy tắc sau là bắt buộc:

- Dùng `realloc` thông qua một con trỏ tạm. Nếu cấp phát thất bại, mảng cũ vẫn nguyên vẹn.
- Mọi hàm `get/set/insert/erase/pop` đều phải kiểm tra biên, không được gây crash.
- `destroy` phải `free` đúng một lần, sau đó gán `NULL`, và không được để rò rỉ bộ nhớ.

## Ví dụ

Đoạn code dưới đây cho thấy các hàm hoạt động nối tiếp nhau như thế nào:

```c
DynamicArray a; da_init(&a, 2);
da_push(&a, 1); da_push(&a, 2); da_push(&a, 3);
// capacity: 2 -> 4, size = 3
da_get(&a, 1);    // = 2
da_insert(&a, 1, 9); // 1, 9, 2, 3
da_erase(&a, 1);     // 1, 2, 3
da_pop(&a);          // 1, 2
da_destroy(&a);
```

### Bài 1: Cài đặt Dynamic Array bằng C

Bạn viết hai file `dynamic_array.h` và `dynamic_array.c`. Mảng chỉ lưu các phần tử kiểu `int`. Struct có dạng như sau:

```c
typedef struct {
  int *data;
  size_t size;      // số phần tử đang dùng
  size_t capacity;  // số ô đã cấp phát
} DynamicArray;
```

**Các hàm bắt buộc.** Mọi hàm trả về `bool` đều phải trả `false` khi có lỗi, và trong trường hợp đó mảng phải giữ nguyên như cũ.

| Hàm | Việc cần làm | Độ phức tạp |
| --- | --- | --- |
| `bool da_init(DynamicArray *a, size_t cap)` | Cấp phát `cap` ô. Nếu `cap == 0` thì cấp 1 ô. Đặt `size = 0`. | $O(1)$ |
| `void da_destroy(DynamicArray *a)` | Giải phóng bộ nhớ, gán `data = NULL`, đặt `size = capacity = 0`. Gọi hai lần liên tiếp vẫn an toàn. | $O(1)$ |
| `bool da_push(DynamicArray *a, int x)` | Thêm `x` vào cuối. Nếu mảng đã đầy thì nhân đôi `capacity` trước. | $O(1)$ trung bình |
| `bool da_pop(DynamicArray *a, int *out)` | Lấy phần tử cuối đưa vào `*out`. Nếu mảng rỗng thì trả `false`. | $O(1)$ |
| `bool da_get(const DynamicArray *a, size_t i, int *out)` | Đọc ô thứ `i` vào `*out`. Nếu `i >= size` thì trả `false`. | $O(1)$ |
| `bool da_set(DynamicArray *a, size_t i, int x)` | Ghi `x` vào ô `i`. Nếu ngoài biên thì trả `false`. | $O(1)$ |
| `bool da_insert(DynamicArray *a, size_t i, int x)` | Chèn `x` tại vị trí `i`, với `0 <= i <= size`. Các phần tử phía sau dịch sang phải. | $O(n)$ |
| `bool da_erase(DynamicArray *a, size_t i)` | Xóa ô `i`. Các phần tử phía sau dịch sang trái. | $O(n)$ |
| `bool da_reserve(DynamicArray *a, size_t cap)` | Đảm bảo `capacity >= cap`. Hàm này không bao giờ làm giảm capacity. | $O(n)$ |
| `bool da_shrink_to_fit(DynamicArray *a)` | Đưa `capacity` về `max(size, 1)`. | $O(n)$ |

**Ràng buộc khi làm bài**

- Chỉ được dùng `malloc`, `realloc`, `free` và `memmove`. Không dùng thư viện container có sẵn.
- Luôn `realloc` thông qua con trỏ tạm. Nếu cấp phát thất bại thì dữ liệu cũ vẫn còn nguyên.
- Thư viện không được gọi `printf`. Khi có lỗi, hãy báo qua giá trị trả về.

**Test mẫu.** Bạn viết các kiểm tra này trong file `test_da.c`, dùng `assert`:

```text
init(cap=2); push 1, 2, 3        -> size=3, capacity=4, [1, 2, 3]
get(1)                           -> true, out=2
insert(1, 9)                     -> [1, 9, 2, 3]
insert(4, 7)                     -> [1, 9, 2, 3, 7]   (chèn cuối hợp lệ)
erase(1)                         -> [1, 2, 3, 7]
pop                              -> true, out=7, [1, 2, 3]
get(5) / set(5, 0) / erase(5)    -> false, mảng không đổi
insert(9, 0)                     -> false
pop 3 lần, rồi pop tiếp          -> lần thứ 4 trả false
reserve(100); shrink_to_fit      -> capacity 100, rồi về 1
```

::tip
Khi `insert`, hãy dùng `memmove(&data[i+1], &data[i], (size-i) * sizeof(int))`. Đừng dùng `memcpy`, vì hai vùng nhớ này chồng lên nhau và `memcpy` không xử lý đúng trường hợp đó.
::

### Bài 2: Đo vết capacity và chi phí copy

Thêm vào struct một biến đếm `size_t copies`, ghi lại tổng số phần tử bị sao chép mỗi khi mảng cấp phát lại.

1. Khởi tạo với `cap = 1`, rồi `push` 10 phần tử. In ra mỗi lần `capacity` thay đổi. Kết quả phải là `1 -> 2 -> 4 -> 8 -> 16`.
2. Viết thêm hai chiến lược tăng dung lượng khác: `+1 ô` và `x1.5`. Bạn chọn chiến lược qua tham số của `da_init`.
3. Với mỗi chiến lược, `push` $n = 10^5$ phần tử rồi in bảng sau:

```text
chien_luoc   n        copies      copies/n
x2           100000   ...         ...
x1.5         100000   ...         ...
+1           100000   ...         ...
```

**Kiểm tra:** với chiến lược nhân đôi, `copies < 2n`. Với chiến lược `+1`, `copies` xấp xỉ $n^2/2$. Hãy viết 3 dòng trong `README.md` để giải thích kết quả bạn thấy.

### Bài 3: Bản C++ `Vec<T>` (nâng cao)

Viết một class template `Vec<T>` trong file `vec.hpp`, tự quản lý bộ nhớ của nó. Bạn không được dùng `std::vector`.

| Thành phần | Yêu cầu |
| --- | --- |
| `Vec()`, `explicit Vec(size_t cap)` | Khởi tạo một mảng rỗng |
| `~Vec()` | Hủy đúng các phần tử đang dùng, rồi giải phóng vùng nhớ |
| Copy constructor, copy assignment | Deep copy (sao chép toàn bộ dữ liệu). Gán `v = v` vẫn phải chạy đúng |
| Move constructor, move assignment | Chỉ chuyển con trỏ sang, và để đối tượng nguồn ở trạng thái rỗng nhưng hợp lệ |
| `push_back(const T&)`, `push_back(T&&)`, `pop_back()` | Giống Bài 1 |
| `T& operator[](size_t)` | Không kiểm tra biên |
| `T& at(size_t)` | Ném `std::out_of_range` nếu ngoài biên |
| `insert(size_t i, const T&)`, `erase(size_t i)` | Giống Bài 1 |
| `size()`, `capacity()`, `empty()`, `reserve(n)` | Giống Bài 1 |
| `T* begin()`, `T* end()` | Để có thể dùng trong vòng lặp `for (auto &x : v)` |

**Test mẫu:** hãy dùng `Vec<std::string>`. Thêm 1000 chuỗi vào, sau đó copy sang một `Vec` khác và sửa bản copy. Kiểm tra bản gốc vẫn không thay đổi. Cuối cùng, move sang một biến mới và kiểm tra nguồn có `size() == 0`.

::tip
Hãy cấp phát vùng nhớ thô bằng `::operator new(cap * sizeof(T))`, rồi dựng từng phần tử bằng placement new: `new (&data[i]) T(x)`. Cách này giúp các ô dư trong capacity không bị gọi constructor một cách không cần thiết.
::
