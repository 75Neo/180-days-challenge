## Giới thiệu

Bài này học cách chuyền một yêu cầu qua một chuỗi người xử lý, và cách chia sẻ đối tượng để tiết kiệm bộ nhớ. Bạn sẽ dùng chúng để làm quy trình duyệt mua nhiều cấp và để vẽ một rừng hàng ngàn cây.

## Kiến thức cần nhớ

### Chain of Responsibility

- Định nghĩa: chuyền yêu cầu dọc theo một chuỗi cho tới khi có người xử lý.
- Mỗi mắt xích tự xử lý, hoặc chuyền cho mắt xích kế tiếp.
- Ví dụ đời thường: như đơn xin duyệt đi qua từng cấp trên.
- Người gửi chỉ đưa yêu cầu cho đầu chuỗi, không cần biết ai sẽ xử lý.
- Muốn thêm một cấp mới thì chỉ cần chen thêm một mắt xích vào chuỗi.

### Ví dụ chuỗi duyệt mua

- Trưởng nhóm duyệt các khoản dưới 1 triệu.
- Trưởng phòng duyệt các khoản dưới 10 triệu.
- Giám đốc duyệt mọi khoản còn lại.
- Ví dụ đời thường: đơn 5 triệu sẽ dừng lại ở trưởng phòng.
- Cần có một mắt xích chặn cuối để đơn không bị rơi mất.

| Mắt xích | Hạn mức | Việc làm |
|---|---|---|
| Trưởng nhóm | Dưới 1 triệu | Tự duyệt, hoặc chuyền tiếp |
| Trưởng phòng | Dưới 10 triệu | Tự duyệt, hoặc chuyền tiếp |
| Giám đốc | Mọi mức còn lại | Chặn cuối chuỗi |

### Flyweight

- Định nghĩa: chia sẻ phần chung, và tách riêng phần khác biệt.
- Hàng ngàn cây dùng chung vài nét vẽ, chỉ khác nhau ở vị trí và màu sắc.
- Ví dụ đời thường: như dùng chung một khuôn in thay vì in từng bản riêng.
- Cache phần chung nên lượng RAM giảm mạnh.
- Phần riêng được lưu ở ngoài, rồi truyền vào khi vẽ.

## Ví dụ

- Đầu vào: đơn mua 5 triệu. Kết quả: trưởng phòng duyệt.
- Giải thích: trưởng nhóm chuyền tiếp, còn trưởng phòng đủ hạn mức để xử lý.

```python
# Mắt xích tự xử hoặc chuyền tiếp
def xu_ly(yeu_cau):
    if yeu_cau <= han_muc:  # đủ quyền thì xử
        return "duyệt"
    return nguoi_ke.xu_ly(yeu_cau)  # không thì chuyền
```

### Bài 1: Chuỗi duyệt chi tiêu

```cpp
struct Request { std::string id; long long amount; std::string purpose; };
class Approver {
 protected: std::shared_ptr<Approver> next;
 public:
  std::shared_ptr<Approver> setNext(std::shared_ptr<Approver> n);   // trả n để nối chuỗi
  virtual std::string handle(const Request &r);                      // mặc định: chuyền tiếp
  virtual ~Approver() = default;
};
```

| Mắt xích | Duyệt khi |
| --- | --- |
| `TeamLead` | `amount < 1.000.000` |
| `Manager` | `amount < 10.000.000` |
| `Director` | `amount < 100.000.000` |
| `Board` (chặn cuối) | Mọi mức còn lại, trả về "cần họp HĐQT" |

```text
5.000.000   -> "Manager duyệt"
500.000     -> "TeamLead duyệt"
2 tỉ        -> "cần họp HĐQT"
Chuỗi không có Board, 2 tỉ -> "không ai xử lý" (không crash, không rơi mất)
```

Chèn thêm `FraudCheck` ở đầu chuỗi: từ chối nếu `purpose` chứa từ khóa bị cấm. Không sửa lớp nào khác.

### Bài 2: Middleware HTTP

Viết một chuỗi xử lý request giả lập: `Logging -> Auth -> RateLimit -> Router`.

- `Auth` từ chối (401) nếu thiếu header `Authorization`.
- `RateLimit` từ chối (429) nếu một IP gửi quá 5 request mỗi giây (dùng đồng hồ giả).
- `Logging` ghi lại mọi request, **kể cả** những request bị từ chối ở phía sau (cần xử lý khi chuỗi trả về).

### Bài 3: Flyweight cho rừng cây (nâng cao)

```cpp
struct TreeType { std::string name; std::string color; std::vector<uint8_t> texture; };  // texture 64 KB
struct Tree { int x, y; const TreeType *type; };
class TreeFactory { public: const TreeType *get(const std::string &name, const std::string &color); size_t typeCount() const; };
```

1. Trồng 1.000.000 cây với 5 loại. In bộ nhớ ước lượng khi mỗi cây giữ texture riêng, và khi dùng Flyweight.
2. `typeCount()` phải bằng 5.
3. Đo bộ nhớ thật bằng `/proc/self/status` (VmRSS) cho cả hai cách.
