## Giới thiệu

Bài này học cách tách riêng dữ liệu, phần hiển thị và phần điều khiển. Nhờ đó, bạn có thể thêm màn hình mới mà không phải sửa phần lõi đã có.

## Kiến thức cần nhớ

### Compound và 3 tầng

- Định nghĩa: compound pattern là một nhóm nhiều pattern cùng phối hợp để giải một bài toán.
- Model giữ nhịp nhạc và các luật thay đổi nhịp.
- View chỉ hiển thị số và đèn chớp theo nhịp.
- Ví dụ đời thường: như DJ, loa và núm vặn, mỗi thứ làm một việc riêng.
- Controller nhận thao tác bấm nút, rồi gọi model thay đổi.

### Luồng người dùng

- DJ bấm tăng nhịp trên controller.
- Controller gọi model để đổi sang nhịp mới.
- Model báo cho mọi view đang lắng nghe.
- Ví dụ đời thường: vặn núm thì loa tự đổi theo.
- Thêm một view mới chỉ cần đăng ký lắng nghe model.

| Tầng | Việc duy nhất | Không làm việc |
|---|---|---|
| Model | Giữ nhịp và luật | Không vẽ màn hình |
| View | Vẽ theo số mới | Không tự đổi số |
| Controller | Nhận thao tác bấm nút | Không giữ dữ liệu |

### Luồng nhịp đập

- Model tự sinh nhịp đều đặn theo thời gian.
- Mỗi nhịp được báo cho các view đang lắng nghe.
- View đèn thì chớp 1 cái, còn view số thì giữ nguyên.
- Ví dụ đời thường: như máy metronome gõ đều cho cả ban nhạc.
- Model không cần biết có bao nhiêu view đang lắng nghe.

### MVC trên web

- Trên web, MVC được chia qua các request: trình duyệt gửi request tới controller, controller gọi model, rồi chọn view để dựng trang trả về.
- Khác với MVC trên máy: view thường không đăng ký lắng nghe model trực tiếp (kiểu Observer), mà nhận dữ liệu mỗi khi controller dựng trang.

## Ví dụ

- Đầu vào: bấm tăng nhịp từ 100 lên 120. Kết quả: con số và đèn cùng đổi theo.
- Giải thích: model đổi một lần, rồi mọi view tự vẽ lại.

```python
# Controller gọi model, model báo view
model.set_nhip(120)  # đổi dữ liệu
for v in views:  # báo từng view
    v.ve_lai(model.nhip)
```

## 💻 Bài tập

Ngôn ngữ: **C++17** (hoặc Java). Giao diện dạng console, cập nhật bằng cách in lại dòng. Nộp vào thư mục `day-107/`.

### Bài 1: Model nhịp DJ

```cpp
struct BeatObserver { virtual void updateBeat() = 0; virtual ~BeatObserver() = default; };
struct BPMObserver  { virtual void updateBPM() = 0;  virtual ~BPMObserver() = default; };
class BeatModel {
 public:
  void on(); void off();
  void setBPM(int bpm);     // kẹp trong [40, 240]
  int  getBPM() const;
  void tick();              // gọi từ vòng lặp thời gian, báo mọi BeatObserver
  void registerObserver(BeatObserver*); void registerObserver(BPMObserver*);
  void removeObserver(BeatObserver*);   void removeObserver(BPMObserver*);
};
```

```text
setBPM(120) -> mọi BPMObserver nhận updateBPM, getBPM = 120
setBPM(500) -> getBPM = 240
off()       -> BPM = 0, tick không phát
```

### Bài 2: View và Controller

| Thành phần | Việc cần làm |
| --- | --- |
| `DJView` | Đăng ký cả hai loại observer. In `"BPM: 120"` và một ký tự `*` mỗi nhịp |
| `BeatController` | Nhận các lệnh `start`, `stop`, `+`, `-`, `set N` từ bàn phím. Gọi model. Bật tắt nút trên view (in trạng thái nút) |
| Strategy | View chỉ gọi controller, và controller có thể được thay bằng một lớp khác |

```text
start; + ; + ; + ; set 90; stop
-> BPM: 60 -> 61 -> 62 -> 63 -> 90 -> 0, nút Start/Stop đổi trạng thái đúng
```

Thêm `BPMGraphView` in một thanh `#` có độ dài tỉ lệ với BPM. Không sửa `BeatModel`.

### Bài 3: Tái dùng view với model khác (nâng cao)

1. Viết `HeartModel` có interface khác (`getHeartRate()`, và observer riêng).
2. Viết `HeartAdapter` để `DJView` dùng được `HeartModel`.
3. Viết `HeartController`: không cho phép đổi nhịp tim, nên lệnh `+` và `-` bị bỏ qua và in cảnh báo.
4. Liệt kê trong `README.md`: MVC này dùng những pattern nào và ở đâu (Observer, Strategy, Composite nếu có, Adapter).
