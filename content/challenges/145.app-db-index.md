## Giới thiệu

Bài này xây một mục lục (index) cho cơ sở dữ liệu mini. Khi cần tìm một dòng cụ thể thì dùng hash; khi cần tìm một đoạn liên tiếp thì dùng cây.

## Kiến thức cần nhớ

### B-tree cho range query

- B-tree giữ các khóa theo thứ tự, và các nút lá được nối với nhau thành một chuỗi.
- Khi chèn vào nút đã đầy, nút đó bị tách (split), và việc tách có thể lan lên trên.
- Range scan: tìm lá đầu tiên của khoảng, rồi quét ngang cho đến khi hết khoảng.
- Fanout (số nhánh) lớn giữ cho cây rất thấp: với fanout 100, 3 tầng đã chứa khoảng 1 triệu khóa, còn 4 tầng chứa khoảng 100 triệu khóa.

### Hash cho point lookup

- Hash ánh xạ mỗi khóa tới vị trí (offset) của bản ghi, với độ phức tạp $O(1)$.
- Nhanh nhất cho các truy vấn tìm một bản ghi, ví dụ tìm mã đơn hàng.
- Không phục vụ được truy vấn theo khoảng vì hash làm mất thứ tự.
- Ví dụ đời thường: tra từ điển bằng số trang đã được đánh dấu sẵn.

### Bloom chặn key vắng

- Bloom filter nhớ toàn bộ các khóa đã có.
- Khóa không có sẽ bị chặn trước khi chạm đến index tốn kém.
- Kết quả "không có" là chắc chắn; kết quả "có" thì cần kiểm tra lại.
- Trình lập kế hoạch (planner): dùng Bloom trước, rồi hash cho tra điểm, và B-tree cho khoảng.

## Ví dụ

- Đầu vào: truy vấn tìm điểm 50 nghìn khóa. Kết quả: giá trị đúng 100% so với quét file.
- Giải thích: hash trỏ đúng offset nên đọc đúng bản ghi.
- Đầu vào: truy vấn khoảng 1000 khóa liên tiếp. Kết quả: trả về đầy đủ và có thứ tự; hash không làm được việc này.
- Giải thích: chỉ B-tree giữ thứ tự nên mới quét được một đoạn.

## 💻 Bài tập

Ngôn ngữ: **C++17**. Dùng Bloom của ngày 30, và hash map của ngày 38. Nộp vào thư mục `day-145-index/`.

### Bài 1: B+ tree trong bộ nhớ

```cpp
template <class K, class V, int ORDER = 32>
class BPlusTree {
 public:
  void insert(const K &k, const V &v);          // khóa trùng thì ghi đè
  std::optional<V> find(const K &k) const;
  bool erase(const K &k);                        // mượn hoặc gộp nút khi thiếu
  std::vector<std::pair<K, V>> range(const K &lo, const K &hi) const;   // lá nối nhau
  int height() const;
  bool check() const;   // lá cùng độ sâu, khóa có thứ tự, số khóa mỗi nút đúng giới hạn
};
```

```text
insert 1..10^6 -> height không quá 5 với ORDER = 32; check = true
range(100, 200) -> 101 cặp theo thứ tự
erase mọi số chẵn -> check = true, find(2) = nullopt
```

Viết test ngẫu nhiên so với `std::map` sau 10^5 thao tác trộn lẫn.

### Bài 2: Ba loại index trên một bảng

Bảng `orders(id, customer_id, created_at, amount)` gồm 10^6 dòng, lưu trong file nhị phân, mỗi dòng cố định 32 byte.

| Index | Trả lời truy vấn |
| --- | --- |
| Hash index trên `id` | `WHERE id = ?` |
| B+ tree trên `created_at` | `WHERE created_at BETWEEN ? AND ?` |
| Bloom trên `customer_id` | Loại nhanh các `customer_id` không tồn tại trước khi quét |

```text
truy_vấn                 quét_toàn_bảng(ms)   có_index(ms)   số_dòng_đọc
id = 123456              ...
created_at trong 1 ngày  ...
customer_id vắng mặt     ...
```

### Bài 3: B+ tree trên đĩa (nâng cao)

1. Mỗi nút là một trang 4096 byte trong file. Đọc và ghi trang bằng `pread` và `pwrite`.
2. Thêm **buffer pool** LRU 256 trang. Đếm số lần đọc đĩa thực sự.
3. So sánh số lần đọc đĩa cho 10.000 truy vấn điểm, với buffer pool có 0, 64, 256 và 1024 trang.
4. Đóng chương trình rồi mở lại: dữ liệu vẫn còn, và `check()` vẫn đúng.
