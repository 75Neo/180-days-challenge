# 📔 Day 165: cache, rate limiter và search
## Giới thiệu
Bạn luyện thiết kế hệ thống mini. Luôn hỏi tải trước khi vẽ.
## Kiến thức cần nhớ
### Khung trình bày 5 bước
- Bước 1: hỏi rõ tải và độ trễ cam kết.
- Bước 2: ước lượng bộ nhớ và băng thông.
- Bước 3: vẽ thành phần và luồng request.
- Ví dụ đời thường: giống hỏi số khách trước khi vẽ quán.
- Bước 4 và 5: đào sâu điểm khó rồi chốt đánh đổi.
### Cache và rate limiter
- Cache LRU LFU giảm tải cho backend.
- Rate limiter chặn khi gọi quá nhanh.
- Ví dụ đời thường: limiter như bảo vệ đếm khách vào.
- Token bucket cho bùng nổ ngắn hạn có giới hạn.
### Search mini
- Trie gợi ý tiền tố, Bloom lọc nhanh.
- Xếp hạng đơn giản bằng độ mới và khớp từ.
- Ví dụ đời thường: giống mục lục cộng danh sách đen.
- Mọi con số ước lượng phải ghi giả định.
```python
# thùng token đơn giản
class ThungToken:  # giới hạn tốc độ gọi
    def __init__(self, suc):
        self.token = suc  # số lượt còn lại
    def goi(self):
        if self.token > 0:  # còn lượt
            self.token -= 1  # trừ một lượt
            return True  # cho qua
        return False  # chặn lại
```
## Ví dụ
- Tải và tỉ lệ trúng cho trước -> tính tải còn lại cho backend.
- 100 request dồn một giây -> limiter cho qua đúng cam kết.

1. Thiết kế cache mini, tính tải backend còn lại.
   Kiểm tra: số học đúng, chính sách đuổi rõ.
2. Thiết kế limiter cho 100 request dồn.
   Kiểm tra: số cho qua và chặn đúng cam kết.
3. Thiết kế search mini bằng Trie và Bloom.
   Kiểm tra: luồng request qua đủ các tầng.
4. Ước lượng bộ nhớ và băng thông một hệ thống.
   Kiểm tra: mỗi số có giả định kèm theo.
5. Chốt bottleneck và đánh đổi bằng số liệu.
   Kiểm tra: nêu rõ giá phải trả của lựa chọn.
