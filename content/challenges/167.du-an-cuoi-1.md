# 📔 Day 167: đặc tả và chia module
## Giới thiệu
Bạn khởi động dự án cuối khóa. Viết rõ trước khi code.
## Kiến thức cần nhớ
### Chốt đề tài
- Đề tài dùng ít nhất 3 kỹ thuật đã học.
- Có dữ liệu thật hoặc giả lập thực tế.
- Ví dụ đời thường: giống chọn món nấu được trong 4 ngày.
- Demo được trong 10 phút.
### Đặc tả yêu cầu
- Yêu cầu hàm là hệ thống làm gì.
- Yêu cầu phi hàm là nhanh và chịu tải bao nhiêu.
- Ví dụ đời thường: giống đơn đặt hàng ghi món và giờ giao.
- Mỗi yêu cầu có mã số để truy vết.
### Chia module và kế hoạch
- Chia thành module nhỏ có sơ đồ phụ thuộc.
- Hợp đồng ghi rõ request và response mỗi cặp.
- Ví dụ đời thường: giống chia việc bếp theo món.
- Lập mốc kiểm chứng cho 3 ngày còn lại.
```python
# ví dụ hợp đồng giữa hai module
hop_dong = {  # thỏa thuận giao tiếp
    "gui": {"user": "u1"},  # bên gửi tạo đúng
    "nhan": {"top10": []},  # bên nhận trả đúng
}
```
## Ví dụ
- 3 yêu cầu hàm -> mỗi yêu cầu truy tới module và ngày kiểm chứng.
- Hai module kề nhau -> request mẫu đi qua cả hai phía đúng.
## 💻 Bài tập
1. Chốt đề tài thỏa 3 điều kiện.
   Kiểm tra: liệt kê 3 kỹ thuật sẽ dùng.
2. Viết 5 yêu cầu hàm có mã số.
   Kiểm tra: mỗi yêu cầu truy tới kịch bản dùng.
3. Viết 3 yêu cầu phi hàm có số cụ thể.
   Kiểm tra: mỗi yêu cầu có ngưỡng đo được.
4. Vẽ sơ đồ 3 module và hợp đồng giao tiếp.
   Kiểm tra: mỗi cặp kề có ví dụ request response.
5. Lập kế hoạch 3 ngày còn lại và phương án cắt giảm.
   Kiểm tra: mỗi ngày có mốc kiểm chứng.
## ❓ Câu hỏi ôn tập
1. Đề tài cần thỏa mấy điều kiện?
2. Yêu cầu hàm khác phi hàm ở đâu?
3. Hợp đồng module ghi gì?
4. Vì sao cấm code sản phẩm hôm nay?
