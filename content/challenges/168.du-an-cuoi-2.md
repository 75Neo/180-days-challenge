## Giới thiệu

Hôm nay bạn xây module lõi rồi đo tốc độ của nó. Mọi nhận định đều phải có số liệu đi kèm.

## Kiến thức cần nhớ

### Module lõi: đúng trước

- Module lõi là phần quan trọng nhất của dự án.
- Hãy chạy đúng trên dữ liệu mẫu nhỏ trước.
- Ví dụ đời thường: giống xây móng nhà trước khi lên tầng.
- Kèm theo các kiểm thử biên như dữ liệu rỗng và dữ liệu một phần tử.

### Benchmark và baseline

- Benchmark là khung đo tốc độ có chuẩn, lặp lại được.
- Baseline là số đo đầu tiên để làm mốc so sánh.
- Ví dụ đời thường: giống cân lần đầu trước khi bắt đầu giảm cân.
- Tách thời gian chạy thuật toán ra khỏi thời gian đọc file.

### Profiling và tối ưu

- Profiling giúp tìm ra 3 hàm tốn thời gian nhất.
- Sửa thuật toán trước, sửa hằng số sau.
- Ví dụ đời thường: giống tìm đoạn kẹt xe nặng nhất để mở đường trước.
- Sau mỗi lần sửa phải đo lại, nếu tệ hơn thì hoàn tác.

```python
# đo thời gian chạy hàm
import time  # đồng hồ đo
bat_dau = time.time()  # mốc bắt đầu
sum(range(1000))  # hàm cần đo
print(time.time() - bat_dau)  # thời gian chạy
```

## Ví dụ

- 5 kiểm thử biên đều xanh trên dữ liệu mẫu.
- Chạy benchmark hai lần, chênh lệch dưới 15%.

## 💻 Bài tập

Dự án cuối, ngày 2. Nộp vào repo `final-project/`.

### Bài 1: Cài đặt lõi

1. Cài module lõi (phần chứa thuật toán chính) thay cho stub.
2. Viết test đơn vị cho lõi: ca thường, ca biên (rỗng, 1 phần tử, dữ liệu trùng, dữ liệu rất lớn), ca lỗi (input sai).
3. Test "vàng": 5 input nhỏ có đáp án tính tay, lưu thành file và so kết quả tự động.

### Bài 2: Benchmark và baseline

1. Thư mục `bench/` chạy lõi trên 3 cỡ dữ liệu (nhỏ, vừa, đúng cỡ `N` yêu cầu). Ghi kết quả ra CSV kèm thông tin máy.
2. Tách thời gian đọc dữ liệu khỏi thời gian chạy thuật toán.
3. Ghi **baseline** vào `BENCHMARK.md`. So với yêu cầu phi chức năng: đạt hay chưa, thiếu bao nhiêu.

### Bài 3: Profile và tối ưu (nâng cao)

1. Profile bằng `perf` hoặc `gprof` (C++), `py-spy` hoặc `cProfile` (Python), hoặc `pprof` (Go). Lưu flame graph.
2. Liệt kê 3 hàm tốn thời gian nhất.
3. Tối ưu theo thứ tự: thuật toán, rồi cấu trúc dữ liệu, cuối cùng mới đến hằng số. Mỗi lần chỉ sửa một thứ, đo lại, rồi ghi vào bảng:

```text
thay_đổi                          p95_trước   p95_sau   giữ_hay_bỏ
đổi list sang heap                ...
bỏ copy chuỗi trong vòng lặp      ...
```

4. Sửa nào làm chậm hơn thì hoàn tác và ghi lại.
