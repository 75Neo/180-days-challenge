## Giới thiệu

Hôm nay bạn thiết kế một hệ thống đọc nhiều. Tải đỉnh có thể gấp mười lần tải trung bình.

## Kiến thức cần nhớ

### Ước lượng tải

- Hỏi rõ yêu cầu trước khi vẽ bất cứ thứ gì.
- Ước lượng bộ nhớ, băng thông và số lượng nút.
- Ví dụ đời thường: giống hỏi số mâm trước khi nấu cỗ.
- Mọi con số phải ghi kèm giả định.

### Cân bằng tải và cache tầng

- Cân bằng tải chia request cho nhiều máy.
- Cache tầng giữ dữ liệu nóng gần người dùng.
- Ví dụ đời thường: giống mở nhiều quầy thu ngân vào giờ cao điểm.
- Với tải đỉnh gấp mười, cần có phương án hấp thụ cụ thể.

### Sharding và chịu lỗi

- Sharding chia dữ liệu theo key ra nhiều shard.
- Key nóng cần được xử lý riêng.
- Ví dụ đời thường: giống chia kho theo mã hàng.
- Khi thêm nút, phải ghi rõ dữ liệu sẽ di chuyển thế nào.

```python
# chia shard đơn giản
def shard(key, n):
    return hash(key) % n  # key nào thì về shard đó
print(shard("user1", 4))  # in số shard chứa key
```

## Ví dụ

- Tải đỉnh gấp mười: có phương án hấp thụ cụ thể.
- 3 key mẫu, trong đó có key nóng: chỉ rõ shard chứa và cách xử lý.

### Bài 2: Sơ đồ triển khai

1. Sơ đồ gồm: load balancer, tầng API (bao nhiêu máy và vì sao), cache, cơ sở dữ liệu.
2. Luồng ghi và luồng đọc, đánh số từng bước.
3. Sinh mã rút gọn: so sánh 3 cách (băm rồi cắt, bộ đếm tăng dần kết hợp base62, ID ngẫu nhiên). Xử lý trường hợp trùng.
4. Tải đỉnh gấp 10: đưa ra phương án hấp thụ cụ thể (tự mở rộng, hàng đợi cho ghi, cache).

### Bài 3: Sharding và key nóng (nâng cao)

2. Với 10^6 key và 4 máy, in số key mỗi máy. Thêm máy thứ 5, in tỉ lệ key phải di chuyển (kỳ vọng khoảng 1/5). So sánh với `hash(key) % n` (kỳ vọng khoảng 4/5).
