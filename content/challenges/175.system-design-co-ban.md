# 📔 Day 175: system design cơ bản
## Giới thiệu
Bạn thiết kế hệ thống đọc nhiều. Tải đỉnh gấp mười trung bình.
## Kiến thức cần nhớ
### Ước lượng tải
- Hỏi yêu cầu trước khi vẽ bất cứ gì.
- Ước lượng bộ nhớ, băng thông, số nút.
- Ví dụ đời thường: giống hỏi số mâm trước khi nấu cỗ.
- Mọi con số phải ghi giả định kèm theo.
### Cân bằng tải và cache tầng
- Cân bằng tải chia request cho nhiều máy.
- Cache tầng giữ dữ liệu hot gần người dùng.
- Ví dụ đời thường: giống mở nhiều quầy thu ngân giờ cao điểm.
- Tải đỉnh gấp mười cần phương án hấp thụ cụ thể.
### Sharding và chịu lỗi
- Sharding chia dữ liệu theo key ra nhiều shard.
- Key nóng cần cách xử lý riêng.
- Ví dụ đời thường: giống chia kho theo mã hàng.
- Thêm nút thì ghi rõ dữ liệu di chuyển thế nào.
```python
# chia shard đơn giản
def shard(key, n):
    return hash(key) % n  # key nào về shard đó
print(shard("user1", 4))  # in số shard chứa key
```
## Ví dụ
- Tải đỉnh gấp mười -> có phương án hấp thụ cụ thể.
- 3 key mẫu gồm key nóng -> chỉ rõ shard chứa và cách xử lý.
## 💻 Bài tập
1. Ước lượng tải cho dịch vụ đọc nhiều.
   Kiểm tra: số học đúng, có giả định.
2. Vẽ sơ đồ triển khai 4 hộp.
   Kiểm tra: luồng request đi đủ các hộp.
3. Thiết kế sharding cho 3 key mẫu có key nóng.
   Kiểm tra: nêu shard chứa và di chuyển khi thêm nút.
4. Thêm cache tầng giảm tải backend.
   Kiểm tra: tính được tải còn lại.
5. Trình bày 10 phút trước nhóm.
   Kiểm tra: đủ yêu cầu, số liệu, sơ đồ, đánh đổi.
## ❓ Câu hỏi ôn tập
1. Vẽ trước hay hỏi tải trước?
2. Cân bằng tải để làm gì?
3. Sharding chia theo gì?
4. Key nóng xử lý thế nào?
