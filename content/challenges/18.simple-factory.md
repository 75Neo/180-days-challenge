## Giới thiệu

Bài này học cách gom chỗ tạo đối tượng về một nơi. Nhờ vậy, bạn không phải rải lệnh tạo đối tượng khắp code nữa.

## Kiến thức cần nhớ

### Rải lệnh tạo gây cứng

- Mỗi nhánh điều kiện gọi thẳng một lớp pizza cụ thể.
- Muốn thêm loại mới, bạn phải mở cửa hàng ra sửa.
- Đổi tên một lớp cũng buộc phải sửa cửa hàng.
- Ví dụ đời thường: mỗi chi nhánh tự nghĩ ra công thức riêng.

### Xưởng đơn giản gom lại

- Mọi cách tạo đối tượng được dồn vào một xưởng chung.
- Cửa hàng hỏi xưởng và nhận lại pizza, không cần biết đó là loại nào.
- Cửa hàng luôn chạy đủ 4 bước chuẩn, bất kể loại pizza.
- Ví dụ đời thường: kho tổng phát hàng cho các chi nhánh.

### Giới hạn của xưởng đơn

- Khi thêm một chiều nữa, ví dụ vùng miền, xưởng sẽ phình to.
- Ví dụ: pizza cùng tên nhưng kiểu New York khác kiểu Chicago.
- Lúc đó bạn cần đến Factory Method, sẽ học ở bài sau.
- Ví dụ đời thường: một kho không thể phục vụ hai miền có khẩu vị khác nhau.

| Tiêu chí | Rải khắp nơi | Qua xưởng |
| --- | --- | --- |
| Biết lớp cụ thể | Rải trong cửa hàng | Gom trong xưởng |
| Thêm loại mới | Mở cửa hàng ra sửa | Chỉ sửa đúng xưởng |
| Dùng lại | Sao chép khối lệnh | Dùng chung một xưởng |

## Ví dụ

- Đầu vào: khách gọi pizza phô mai. Kết quả: xưởng trả về đúng loại, còn cửa hàng chạy đủ 4 bước.
- Giải thích: kiến thức về lớp cụ thể chỉ nằm ở một chỗ duy nhất.

## 💻 Bài tập

Ngôn ngữ: **C++17** (hoặc Java). Nộp vào thư mục `day-018/`.

### Bài 1: Pizza Store với Simple Factory

```cpp
class Pizza {
 public:
  virtual std::string name() const = 0;
  virtual void prepare(); virtual void bake(); virtual void cut(); virtual void box();
  const std::vector<std::string> &log() const;   // ghi lại các bước để test
  virtual ~Pizza() = default;
};
class SimplePizzaFactory { public: std::unique_ptr<Pizza> create(const std::string &type) const; };
class PizzaStore {
 public:
  explicit PizzaStore(const SimplePizzaFactory &f);
  std::unique_ptr<Pizza> order(const std::string &type);  // create + 4 bước
};
```

Hãy cài đặt các lớp trên, với kết quả `name()` theo bảng sau:

| Loại | `name()` |
| --- | --- |
| `"cheese"` | `"Pizza phô mai"` |
| `"pepperoni"` | `"Pizza xúc xích"` |
| `"veggie"` | `"Pizza rau"` |
| `"clam"` | `"Pizza nghêu"` |

**Ràng buộc**

- `PizzaStore` không được `#include` bất kỳ lớp pizza cụ thể nào.
- Nếu loại pizza không tồn tại: `create` trả về `nullptr`, còn `order` ném `std::invalid_argument`.

```text
order("cheese")  -> name "Pizza phô mai", log = [prepare, bake, cut, box]
order("sushi")   -> ném invalid_argument
```

### Bài 2: Thêm loại mới

1. Thêm loại `"seafood"`, và chứng minh rằng chỉ có `SimplePizzaFactory` cùng file lớp mới bị thay đổi.
2. Đổi `create` sang dùng **bảng đăng ký**: `std::unordered_map<std::string, std::function<std::unique_ptr<Pizza>()>>`. Viết thêm hàm `registerType(name, creator)`. Khi đó, bạn có thể thêm loại mới lúc chạy mà không cần sửa factory.

### Bài 3: Xưởng tài liệu (nâng cao)

`DocumentFactory::create(path)` sẽ chọn lớp dựa vào đuôi file: `.txt` ra `TextDocument`, `.csv` ra `SpreadsheetDocument`, `.md` ra `MarkdownDocument`. Mỗi lớp đều có hàm `std::string summary()`.

- `TextDocument`: số dòng và số từ.
- `SpreadsheetDocument`: số hàng và số cột.
- `MarkdownDocument`: số heading `#`.

Nếu đuôi file không được hỗ trợ, hãy báo lỗi rõ ràng. Viết `main` nhận danh sách file từ dòng lệnh, rồi in `summary()` của từng file.
