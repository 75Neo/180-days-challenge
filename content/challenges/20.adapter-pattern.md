## Giới thiệu

Bài này học về adapter, tức là một cục chuyển đổi giao diện. Bạn sẽ cho một con gà tây đóng giả làm vịt.

## Kiến thức cần nhớ

### Adapter là gì

- Adapter chuyển giao diện cũ thành giao diện mà phía khách đang chờ.
- Không sửa bên cũ, cũng không sửa bên mới.
- Ví dụ đời thường: cục chuyển phích cắm khi đi du lịch.
- Nhờ đó, hai bên không khớp nhau vẫn có thể làm việc cùng nhau.

### Gà tây giả vịt

- Vịt kêu "quạc" và bay xa, còn gà tây kêu "cục tác" và chỉ bay được quãng ngắn.
- Adapter đứng giữa: bên ngoài trông như vịt, bên trong là gà tây.
- Khi được yêu cầu kêu, adapter dịch thành tiếng "cục tác".
- Khi được yêu cầu bay xa, adapter cho gà tây bay ngắn nhiều lần.
- Ví dụ đời thường: phiên dịch viên đứng giữa hai người.

### Hai biến thể và cách phân biệt

- Bọc đối tượng: giữ gà tây ở bên trong. Cách này linh hoạt.
- Kế thừa lớp: vừa là vịt, vừa là gà tây. Cách này gọn, nhưng cứng nhắc.
- Nên ưu tiên bọc đối tượng.
- Ví dụ đời thường: thuê dịch vụ dịch thuật, hay tự học tiếng.

| Tiêu chí | Bọc đối tượng | Kế thừa lớp |
| --- | --- | --- |
| Cơ chế | Giữ tham chiếu | Kế thừa |
| Dùng cho lớp con của gà | Được | Không |
| Cần ngôn ngữ gì | Mọi nơi | Cần đa kế thừa |

## Ví dụ

- Đầu vào: một bầy vịt đang kêu. Kết quả: nghe thấy tiếng cục tác, nhưng vẫn chấp nhận được.
- Giải thích: bộ chuyển đổi dịch đúng chuẩn vịt ra bên ngoài.

## 💻 Bài tập

Ngôn ngữ: **C++17** (hoặc Java). Nộp vào thư mục `day-020/`.

### Bài 1: Gà tây giả vịt (object adapter)

```cpp
struct Duck   { virtual std::string quack() = 0;  virtual std::string fly() = 0; virtual ~Duck() = default; };
struct Turkey { virtual std::string gobble() = 0; virtual std::string fly() = 0; virtual ~Turkey() = default; };
```

| Lớp | Hành vi |
| --- | --- |
| `MallardDuck : Duck` | `quack()` trả về `"Quạc"`, `fly()` trả về `"Bay xa"` |
| `WildTurkey : Turkey` | `gobble()` trả về `"Cục tác"`, `fly()` trả về `"Bay ngắn"` |
| `TurkeyAdapter : Duck` | Giữ một `Turkey&`. `quack()` gọi `gobble()`. `fly()` gọi `turkey.fly()` 5 lần, rồi nối các kết quả lại bằng dấu cách `" "` |
| `DuckAdapter : Turkey` | Làm ngược lại. `fly()` của vịt chỉ được gọi 1 lần cho mỗi 5 lần `fly()` của gà tây. 4 lần còn lại trả về `"Nghỉ"` |

Viết `void testDuck(Duck &d)` để in `quack()` và `fly()`. Truyền cả `MallardDuck` lẫn `TurkeyAdapter` vào hàm này.

```text
testDuck(TurkeyAdapter(turkey)) -> "Cục tác", "Bay ngắn Bay ngắn Bay ngắn Bay ngắn Bay ngắn"
DuckAdapter gọi fly 6 lần       -> "Bay xa", "Nghỉ", "Nghỉ", "Nghỉ", "Nghỉ", "Bay xa"
```

### Bài 2: Class adapter và so sánh

1. Viết `TurkeyClassAdapter : public Duck, private WildTurkey` bằng cách dùng đa kế thừa.
2. Tạo `OldTurkey : WildTurkey`, ghi đè `fly()` để trả về `"Không bay nổi"`. Object adapter dùng được với `OldTurkey`, còn class adapter thì không. Viết test để chứng minh điều này.
3. Viết bảng so sánh hai biến thể vào `README.md`.

### Bài 3: Adapter cho thư viện thật (nâng cao)

Ứng dụng của bạn có interface sau:

```cpp
struct Logger { virtual void log(Level lv, const std::string &msg) = 0; };  // Level: Info, Warn, Error
```

Ngoài ra, có hai "thư viện ngoài" với API khác nhau. Bạn tự viết bản giả lập, và **không được sửa** các lớp này:

```cpp
class LegacyFileLog { public: void write(const char *line); };                       // ghi "[I] msg"
class CloudLog { public: void send(std::map<std::string, std::string> fields); };    // {"severity", "text"}
```

Hãy viết `LegacyFileLogAdapter` và `CloudLogAdapter`. Ứng dụng chỉ biết đến `Logger`. Viết test cho từng adapter để kiểm tra định dạng đầu ra có đúng không.

```text
log(Warn, "đĩa đầy") qua LegacyFileLogAdapter -> write("[W] đĩa đầy")
log(Error, "mất kết nối") qua CloudLogAdapter  -> send({severity: "ERROR", text: "mất kết nối"})
```
