## Giới thiệu

Bài này ôn lại 5 nguyên lý SOLID qua ví dụ con vịt và tiệm pizza. Mục tiêu là bạn học cách thêm tính năng mới mà không phải sửa code cũ.

## Kiến thức cần nhớ

### S — Đơn trách nhiệm

- Một lớp chỉ nên có một lý do để thay đổi.
- Lớp ôm quá nhiều việc rất dễ bị hỏng dây chuyền: sửa chỗ này kéo theo lỗi ở chỗ khác.
- Ví dụ đời thường: mỗi người chỉ làm một nghề cho chuyên.
- Ví dụ trong code: tách lớp in hóa đơn ra khỏi lớp lưu đơn hàng.

### O — Mở rộng không sửa đổi

- Muốn thêm tính năng thì thêm lớp mới.
- Đừng mở lớp cũ ra vá lại mỗi lần có yêu cầu mới.
- Ví dụ đời thường: cắm thêm một ổ điện, chứ không phải đục tường.
- Ví dụ trong code: vịt biết bay tên lửa là một lớp mới, còn lớp Vịt giữ nguyên.

### L, I, D còn lại

- L (Liskov): lớp con phải dùng thay được cho lớp cha mà không gây bất ngờ.
- I (Interface Segregation): đừng ép một lớp phải dùng những thứ nó không cần.
- D (Dependency Inversion): hãy phụ thuộc vào giao diện (trừu tượng), không phụ thuộc vào lớp cụ thể.
- Ví dụ đời thường: chiếc remote chỉ cần các nút bấm chung.

| Chữ | Câu hỏi tự vấn |
| --- | --- |
| S | Lớp này có mấy lý do để phải thay đổi? |
| O | Thêm mới có buộc phải sửa code cũ không? |
| L | Lớp con có làm điều gì bất ngờ so với lớp cha không? |
| D | Đang phụ thuộc vào cái cụ thể hay cái trừu tượng? |

## Ví dụ

- Đầu vào: thêm kiểu bay tên lửa cho đàn vịt. Kết quả: tạo lớp mới, lớp Vịt không bị động vào.
- Giải thích: đây đúng là chữ O, vì ta mở rộng được mà không sửa code cũ.

## 💻 Bài tập

Ngôn ngữ: **C++17** (hoặc Java). Nộp vào thư mục `day-003/`. Mỗi bài có hai thư mục: `before/` chứa code ban đầu, và `after/` chứa code sau khi đã sửa.

### Bài 1: Tách trách nhiệm (S)

Cho class sau. Hãy viết lại đúng theo đề trong `before/order.cpp`:

```cpp
class Order {
 public:
  void addItem(std::string name, double price, int qty);
  double total() const;                   // tính tiền
  std::string toInvoiceText() const;      // định dạng hóa đơn
  void saveToFile(const std::string &p);  // ghi file
  void sendEmail(const std::string &to);  // gửi email (chỉ in ra console)
};
```

**Yêu cầu:** tách class này thành 4 lớp, mỗi lớp chỉ có một lý do để thay đổi.

| Lớp | Trách nhiệm |
| --- | --- |
| `Order` | Giữ danh sách món và tính `total()` |
| `InvoiceFormatter` | Định dạng hóa đơn: `std::string format(const Order&)` |
| `OrderRepository` | Lưu đơn hàng: `void save(const Order&, const std::string &path)` |
| `EmailSender` | Gửi email: `void send(const std::string &to, const std::string &body)` |

Trong `README.md`, với mỗi lớp, hãy viết 1 ví dụ về một thay đổi yêu cầu mà chỉ cần sửa đúng lớp đó.

### Bài 2: Mở rộng không sửa (O) và đảo phụ thuộc (D)

Code ban đầu tính giảm giá bằng một chuỗi `if`:

```cpp
double discount(const std::string &type, double total) {
  if (type == "none") return 0;
  if (type == "percent10") return total * 0.1;
  if (type == "fixed50") return total > 50 ? 50 : 0;
  return 0;
}
```

**Yêu cầu:**

1. Tạo interface: `class DiscountPolicy { public: virtual double apply(double total) const = 0; virtual ~DiscountPolicy() = default; };`
2. Viết 3 lớp: `NoDiscount`, `PercentDiscount(double rate)`, `FixedDiscount(double amount, double minTotal)`.
3. `Checkout` nhận một `std::unique_ptr<DiscountPolicy>` qua constructor. Lớp `Checkout` không được `#include` bất kỳ lớp cụ thể nào.
4. Thêm `BuyOver200Get15Percent` mà **không sửa** dòng nào của `Checkout` và của 3 lớp cũ.

Kết quả mong đợi:

```text
total=100, NoDiscount             -> 100
total=100, PercentDiscount(0.1)   -> 90
total=40,  FixedDiscount(50, 50)  -> 40
total=120, FixedDiscount(50, 50)  -> 70
total=250, BuyOver200Get15Percent -> 212.5
```

### Bài 3: Phát hiện vi phạm L và I (nâng cao)

1. Viết `Rectangle` có `setWidth`, `setHeight` và `area`. Cho `Square` kế thừa `Rectangle`. Viết hàm test `void resize(Rectangle &r) { r.setWidth(5); r.setHeight(4); assert(r.area() == 20); }`. Hãy chứng minh rằng `Square` làm test này fail.
2. Sửa lại thiết kế để test không còn fail. Gợi ý: tách một interface `Shape { virtual double area() const = 0; }`.
3. Cho interface `IMachine { print(); scan(); fax(); }`. Một máy in rẻ tiền chỉ in được, nhưng lại buộc phải cài đặt các hàm `scan` và `fax` rỗng. Hãy tách thành `IPrinter`, `IScanner`, `IFax` để máy in không phải cài những hàm mình không dùng đến.
