## Giới thiệu

Bài này học Composite, cách xử lý một cây mà các thành phần được đối xử đồng nhất. Bạn sẽ dùng nó cho một thực đơn có nhiều tầng lồng nhau.

## Kiến thức cần nhớ

### Định nghĩa Composite

- Gộp các đối tượng thành một cây để biểu diễn cấu trúc phân cấp.
- Phía người dùng đối xử với nhóm và với phần tử lá như nhau.
- Hai từ khóa quan trọng: cây, và đồng nhất.
- Ví dụ đời thường: giống như thư mục chứa file và thư mục con, mở ra đều như nhau.

### Thực đơn dạng cây

- Thực đơn tổng chứa các thực đơn con, còn thực đơn con chứa các món lá.
- Một nhóm giữ danh sách các con. Khi gọi in, nhóm sẽ gọi lan xuống từng con.
- Lá chỉ in chính nó và không có con.
- Ví dụ đời thường: như gọi cả bàn ăn, bếp sẽ tự lo từng món.

### Trong suốt và an toàn

- Trong suốt: các thao tác thêm bớt được đặt ở giao diện chung, nên người dùng không cần rẽ nhánh.
- An toàn: thao tác thêm bớt chỉ có ở nhóm, còn lá thì gọn sạch.
- Với trong suốt, lỗi được phát hiện lúc chạy. Với an toàn, lỗi được phát hiện lúc biên dịch.
- Bài này chọn trong suốt vì nó đơn giản hơn cho người dùng.

| Khía cạnh | Trong suốt | An toàn |
|---|---|---|
| Giao diện chung | Có thêm bớt | Chỉ có các thao tác chung |
| Phía người dùng | Không cần rẽ nhánh | Phải kiểm tra loại nhóm |
| Lá | Mang theo các phương thức thừa | Gọn sạch |

## Ví dụ

- Đầu vào: gọi in trên thực đơn tổng. Kết quả: mọi món ở mọi tầng được in đúng một lần.
- Giải thích: yêu cầu được lan đệ quy từ nhóm cha xuống các lá.
- Đầu vào: thêm một con vào món lá trong bản trong suốt. Kết quả: lá từ chối rõ ràng, cây không thay đổi.
- Giải thích: lá không có con nên phải báo lỗi.

## 💻 Bài tập

Ngôn ngữ: **C++17** (hoặc Java). Nộp vào thư mục `day-067/`.

### Bài 1: Thực đơn dạng cây (trong suốt)

```cpp
class MenuComponent {
 public:
  virtual std::string name() const = 0;
  virtual void print(std::ostream &os, int indent = 0) const = 0;
  virtual double price() const { throw std::logic_error("không hỗ trợ"); }
  virtual bool vegetarian() const { throw std::logic_error("không hỗ trợ"); }
  virtual void add(std::shared_ptr<MenuComponent>) { throw std::logic_error("không hỗ trợ"); }
  virtual void remove(const MenuComponent *) { throw std::logic_error("không hỗ trợ"); }
  virtual ~MenuComponent() = default;
};
class MenuItem : public MenuComponent { ... };   // lá
class Menu : public MenuComponent { ... };       // nhóm, giữ vector các con
```

Dựng cây: `ALL MENUS` gồm `PANCAKE HOUSE`, `DINER` và `CAFE`. `DINER` chứa thêm thực đơn con `DESSERT`.

```text
allMenus.print() -> in mọi món mọi tầng, thụt lề theo độ sâu, mỗi món đúng 1 lần
item.add(...)    -> ném logic_error, cây không đổi
```

### Bài 2: Thao tác trên cả cây

Thêm các hàm đệ quy sau vào giao diện chung:

| Hàm | Với lá | Với nhóm |
| --- | --- | --- |
| `double totalPrice()` | Giá của chính nó | Tổng giá các con |
| `int countItems()` | 1 | Tổng số món của các con |
| `int depth()` | 0 | 1 + độ sâu lớn nhất của các con |
| `std::shared_ptr<MenuComponent> find(name)` | So sánh tên | Tìm trong các con |

### Bài 3: Bản an toàn và hệ thống file (nâng cao)

1. Viết lại theo kiểu **an toàn**: `add` và `remove` chỉ có ở `Menu`. Viết một dòng code gọi `add` trên một lá, và chứng minh rằng bản an toàn không biên dịch được. Viết bảng so sánh hai cách.
2. Mô hình thư mục: `File(name, size)` và `Directory`. Viết `du` (tổng dung lượng), `tree` (in cây) và `findLarger(n)` (các file lớn hơn `n` byte). Đọc một cây thư mục thật bằng `std::filesystem` để dựng Composite.
