## Giới thiệu

Bài này học Decorator trong thư viện đọc và ghi file. Bạn sẽ dùng nó để chồng các tầng đệm và tầng đếm dòng lên nhau.

## Kiến thức cần nhớ

### Luồng chuẩn là Decorator

- Lõi là luồng đọc thô từ file hoặc bộ nhớ.
- Quanh lõi là các tầng bọc: đệm, đếm dòng, đọc theo kiểu dữ liệu, nén.
- Mọi mắt xích đều là luồng, nên chúng có thể bọc lẫn nhau.
- Ví dụ đời thường: như ống nước nối thêm đầu lọc, lõi vẫn là ống nước.

### Đường đi của yêu cầu đọc

- Tầng ngoài nhận yêu cầu đọc 1 ký tự thì hỏi tầng bên trong.
- Tầng đệm còn dữ liệu thì trả về ngay, hết thì hỏi lõi file.
- Mỗi tầng chỉ làm đúng việc của mình, rồi ủy thác phần còn lại cho tầng trong.
- Ví dụ đời thường: như hỏi kho, kho hết hàng thì mới hỏi nhà máy.

| Khía cạnh | Cà phê Starbuzz | Luồng vào-ra |
|---|---|---|
| Lõi | Đồ uống nền | Luồng đọc thô |
| Lớp bọc | Sữa, kem | Đệm, đếm dòng, nén |
| Thêm mới | Topping mới | Tầng đọc mới |

### Thứ tự bọc

- Với cà phê, đổi thứ tự topping thì giá vẫn như vậy.
- Với luồng, đổi thứ tự có thể làm sai kết quả: ví dụ giải nén phải nằm trong tầng đọc kiểu dữ liệu.
- Người chồng các tầng phải hiểu ý nghĩa của từng tầng.
- Hãy ghi rõ thứ tự bọc và lý do trong tài liệu.

### Tự viết tầng chữ thường

- Lớp mới cũng là một luồng, nên có thể dùng ở mọi nơi cần luồng.
- Giữ một luồng bên trong, đọc từng ký tự rồi đổi chữ hoa thành chữ thường.
- Không sửa thư viện cũ, chỉ thêm một mắt xích mới.
- Chồng quá nhiều tầng thì sẽ khó debug và khó đọc.

## Ví dụ

- Đầu vào: đọc file qua một tầng đệm. Kết quả: nhận đúng từng ký tự, nhưng số lần chạm vào đĩa ít hơn.
- Giải thích: kho đệm trả về ngay khi còn dữ liệu.
- Đầu vào: chuỗi `HeLLo` đi qua tầng chữ thường. Kết quả: `hello`.
- Giải thích: chỉ chữ hoa bị đổi, chữ thường và các ký tự khác giữ nguyên.

## 💻 Bài tập

Ngôn ngữ: **C++17** (hoặc Java với `FilterInputStream`). Nộp vào thư mục `day-071/`.

### Bài 1: Chuỗi luồng đọc

```cpp
class InputStream {
 public:
  virtual int read() = 0;                   // trả byte 0..255, hết dữ liệu trả -1
  virtual ~InputStream() = default;
};
class FilterInputStream : public InputStream {
 protected: std::unique_ptr<InputStream> in;
 public: explicit FilterInputStream(std::unique_ptr<InputStream> in);
  int read() override { return in->read(); }
};
```

| Lớp | Việc cần làm |
| --- | --- |
| `FileInputStream(path)` | Đọc thô, mỗi lần `read()` là một lần `fread` 1 byte. Đếm số lần gọi hệ thống |
| `MemoryInputStream(std::string)` | Đọc từ bộ nhớ |
| `BufferedInputStream(in, size)` | Đọc theo khối `size` byte vào bộ đệm |
| `LowerCaseInputStream(in)` | Đổi `A-Z` thành `a-z` |
| `LineCountingInputStream(in)` | Đếm số ký tự `\n`, có hàm `lineCount()` |

```text
LowerCase(Memory("HeLLo")) đọc hết           -> "hello"
LineCounting(Memory("a\nb\nc")) đọc hết      -> lineCount = 2
Buffered(File(1 MB), 4096)                   -> số lần gọi đọc file thô ~ 256 thay vì ~10^6
```

### Bài 2: Thứ tự bọc có ý nghĩa

Thêm `Rot13InputStream` và `Base64DecodeInputStream`.

1. Mã hóa chuỗi `"Xin Chao"` bằng Rot13 rồi đến Base64, và lưu vào `secret.txt`.
2. Chồng các tầng đọc đúng thứ tự để nhận lại `"xin chao"` (chữ thường). Sau đó chồng sai thứ tự và ghi lại kết quả sai.
3. Viết comment trong code: thứ tự đúng là gì và vì sao.

### Bài 3: Luồng ghi và nén (nâng cao)

1. Viết phía ghi tương ứng: `OutputStream`, `FileOutputStream`, `BufferedOutputStream` (nhớ `flush` trong destructor), và `UpperCaseOutputStream`.
2. Viết `RleOutputStream` và `RleInputStream`: nén các chuỗi lặp dài dưới dạng `(số lần, byte)`. Kiểm tra rằng ghi rồi đọc lại đúng.
3. Đo thời gian ghi 10 MB, có và không có `BufferedOutputStream`.

### ✅ Tiêu chí hoàn thành

- [ ] Test mẫu pass.
- [ ] Số lần gọi hệ thống giảm rõ nhờ tầng đệm (có số đo).
- [ ] Bài 2 ghi lại được kết quả sai khi đổi thứ tự.
- [ ] Không mất dữ liệu cuối file khi quên gọi `flush` (destructor đảm nhiệm việc này).
