## Giới thiệu

Bài này học Bridge, cách tách phần điều khiển khỏi phần thiết bị, và Builder, cách dựng một đối tượng phức tạp từng bước. Bạn sẽ dùng chúng để thêm hãng TV mới hoặc món ăn mới mà không làm vỡ code.

## Kiến thức cần nhớ

### Bridge

- Định nghĩa: tách phần trừu tượng khỏi phần cài đặt bằng một "cầu" nối giữa chúng.
- Remote giữ một cầu tới TV. Khi bấm nút, remote chuyển lời tới TV.
- Ví dụ đời thường: như remote đa năng, bấm nút là TV thực hiện.
- Thêm một hãng TV mới chỉ cần thêm 1 lớp.
- Không phải nhân số lớp theo tích của hai chiều.

| Cách làm | Thêm hãng mới | Thêm loại remote mới |
|---|---|---|
| Kế thừa, liệt kê tất cả | Nhân thêm nhiều lớp | Nhân thêm nhiều lớp |
| Bridge qua cầu | Chỉ thêm 1 lớp TV | Chỉ thêm 1 lớp remote |

### Builder

- Định nghĩa: dựng một đối tượng phức tạp qua nhiều bước nhỏ.
- Thay thế constructor khổng lồ với nhiều tham số rối rắm.
- Ví dụ đời thường: như gọi cơm, chọn từng món một.
- Mỗi bước trả về chính builder để có thể nối chuỗi lệnh.
- Bước cuối gọi `build` để tạo ra thành phẩm.

```python
# Builder dựng bữa ăn từng bước
meal = (MealBuilder()
    .them_mon_chinh("cơm gà")  # chọn món chính
    .them_nuoc("trà đá")  # chọn nước
    .build())  # chốt đơn
print(meal)
```

### Khi nào dùng

- Dùng Bridge khi hai chiều có thể cùng thay đổi một cách độc lập.
- Dùng Builder khi đối tượng có quá nhiều tùy chọn.
- Không dùng Bridge cho quan hệ một chiều đơn giản.
- Không dùng Builder cho đối tượng chỉ có 1-2 trường.

## Ví dụ

- Đầu vào: thêm hãng TV thứ tư. Kết quả: chỉ thêm 1 lớp TV mới.
- Giải thích: remote cũ giữ nguyên, vì nó chỉ nói chuyện qua cầu.
- Đầu vào: bữa ăn thiếu nước. Kết quả: builder báo lỗi trước khi build.
- Giải thích: kiểm tra từng bước rõ ràng hơn một constructor dài.

### Bài 1: Bridge cho remote và TV

```cpp
struct TV {   // implementor
  virtual void on() = 0; virtual void off() = 0; virtual void tuneChannel(int ch) = 0;
  virtual int channel() const = 0; virtual ~TV() = default;
};
class RemoteControl {   // abstraction
 protected: TV &tv;
 public:
  explicit RemoteControl(TV &t);
  virtual void on(); virtual void off(); virtual void setChannel(int ch);
  virtual ~RemoteControl() = default;
};
class ConcreteRemote : public RemoteControl {
 public: void nextChannel(); void previousChannel(); void favorite(int slot); void setFavorite(int slot, int ch);
};
```

Các TV cụ thể: `SonyTV`, `SamsungTV`, `LgTV`. Mỗi hãng có dải kênh hợp lệ khác nhau: Sony 1-99, Samsung 1-999, LG 1-500. Kênh không hợp lệ thì ném lỗi.

```text
ConcreteRemote(SonyTV).setChannel(5); nextChannel() -> Sony kênh 6
ConcreteRemote(SonyTV).setChannel(99); nextChannel() -> quay vòng về 1
```

Đếm số lớp cần viết theo cách kế thừa thuần (mỗi loại remote nhân với mỗi hãng TV) và theo Bridge, khi có 3 loại remote và 3 hãng TV. Ghi vào `README.md`.

### Bài 2: Builder cho đối tượng nhiều tùy chọn

```cpp
class HttpRequest { /* method, url, headers, query, body, timeoutMs, retries */ };
class HttpRequestBuilder {
 public:
  explicit HttpRequestBuilder(std::string url);
  HttpRequestBuilder &method(std::string m);
  HttpRequestBuilder &header(std::string k, std::string v);
  HttpRequestBuilder &query(std::string k, std::string v);
  HttpRequestBuilder &body(std::string b);
  HttpRequestBuilder &timeout(int ms);
  HttpRequestBuilder &retries(int n);
  HttpRequest build() const;   // kiểm tra hợp lệ
};
```

| Luật kiểm tra trong `build()` | Lỗi |
| --- | --- |
| `GET` có `body` | `invalid_argument` |
| `timeout <= 0` hoặc `retries < 0` | `invalid_argument` |
| URL không bắt đầu bằng `http://` hoặc `https://` | `invalid_argument` |

Viết `HttpRequest::toString()` để in ra dạng request HTTP thô. Test với 5 request hợp lệ và 3 request lỗi.
