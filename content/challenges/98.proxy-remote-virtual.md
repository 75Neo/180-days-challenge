## Giới thiệu

Bài này học Proxy, một đối tượng đại diện đứng giữa người dùng và đối tượng thật. Bạn sẽ dùng nó để gọi tới một máy ở xa, và để tải các ảnh nặng mà không phải chờ đợi.

## Kiến thức cần nhớ

### Định nghĩa Proxy

- Định nghĩa: một đối tượng đại diện cho đối tượng khác, để kiểm soát việc truy cập.
- Đại diện và đối tượng thật cùng tuân theo một giao diện.
- Ví dụ đời thường: như lễ tân nhận yêu cầu thay cho giám đốc.
- Người dùng không biết mình đang nói chuyện với đại diện.
- Từ khóa: đại diện, và kiểm soát truy cập.

### Remote proxy

- Định nghĩa: một đại diện ở phía địa phương, thay mặt cho một máy ở xa qua mạng.
- Người dùng gọi đại diện như thể đang gọi máy thật ngay tại chỗ.
- Ví dụ đời thường: như gọi shipper thay vì tự đến quán ở xa.
- Đại diện lo việc đóng gói yêu cầu để gửi qua mạng.
- Phía bên kia mở gói yêu cầu rồi hỏi máy thật.

| Loại proxy | Vấn đề | Cách giải quyết |
|---|---|---|
| Remote | Máy ở xa, gọi khó | Đại diện ở địa phương |
| Virtual | Ảnh nặng, tải chậm | Hiện tạm, tải sau |
| Bảo vệ | Cần kiểm tra quyền | Chặn trước khi vào |

### Virtual proxy

- Định nghĩa: giữ chỗ trước, rồi tải các thứ nặng sau.
- Danh sách hiện ngay, còn ảnh bìa thì tải dần từng cái.
- Ví dụ đời thường: như khung xám hiện ra trong lúc chờ ảnh tải xong.
- Nếu tải hết mọi thứ trước khi hiện thì người dùng phải chờ rất lâu.
- Khi người dùng bấm vào món nào thì mới tải phần nặng của món đó.

## Ví dụ

- Đầu vào: hỏi tồn kho của một máy kẹo ở xa. Kết quả: gọi tới đại diện đặt tại văn phòng.
- Giải thích: đại diện chuyển lời qua mạng tới máy thật.

```python
# Đại diện kiểm soát trước khi gọi hàng thật
class Proxy:
    def lay_kho(self):
        if not self.quyen:  # kiểm tra trước
            return "từ chối"
        return self.may_that.lay_kho()  # chuyển lời
```

## 💻 Bài tập

Ngôn ngữ: **C++17** (hoặc Java). Dùng `GumballMachine` và `GumballMonitor` của ngày 86. Nộp vào thư mục `day-098/`.

### Bài 1: Remote proxy qua socket

```cpp
struct GumballMachineRemote {
  virtual int count() = 0; virtual std::string location() = 0; virtual std::string state() = 0;
  virtual ~GumballMachineRemote() = default;
};
```

| Thành phần | Việc cần làm |
| --- | --- |
| `GumballServer` | Chạy `GumballMachine` thật, lắng nghe TCP ở cổng 5000. Nhận các dòng `COUNT`, `LOCATION`, `STATE`, và trả về 1 dòng kết quả |
| `GumballStub : GumballMachineRemote` | Mở socket, gửi lệnh, đọc kết quả. Nếu có lỗi mạng thì ném `RemoteException` |
| `GumballMonitor` | Chỉ biết `GumballMachineRemote&`, không cần biết đó là máy thật hay stub |

```text
Monitor(máy thật) và Monitor(stub tới server) in cùng báo cáo
Tắt server rồi gọi stub -> RemoteException, monitor in "không liên lạc được"
```

Chạy 3 server ở 3 cổng (tương ứng với 3 máy ở 3 thành phố). Monitor in báo cáo của cả 3.

### Bài 2: Virtual proxy cho ảnh bìa

```cpp
struct Icon { virtual int width() = 0; virtual int height() = 0; virtual std::string paint() = 0; virtual ~Icon() = default; };
class ImageIcon : public Icon { /* constructor tải ảnh: giả lập sleep 2 giây */ };
class ImageProxy : public Icon {
  // chưa tải xong: width/height trả 800x600, paint trả "Đang tải ảnh bìa..."
  // lần gọi paint đầu tiên: khởi động tải ở luồng nền
  // tải xong: ủy thác mọi lời gọi cho ImageIcon
};
```

```text
Tạo 20 ImageProxy -> tức thì (dưới 10 ms)
paint() ngay lập tức -> "Đang tải ảnh bìa..."
paint() sau 3 giây   -> nội dung ảnh thật
Chỉ ảnh nào được paint mới tải (đếm số lần tải)
```

### Bài 3: Caching proxy (nâng cao)

`WeatherService::forecast(city)` giả lập một lệnh gọi API mất 500 ms.

1. Viết `CachingWeatherProxy` với cùng giao diện: cache kết quả trong 10 phút theo `city` (dùng đồng hồ giả để test).
2. Viết `LoggingWeatherProxy` ghi lại thời gian của mỗi lần gọi. Chồng 2 proxy lên nhau.
3. Viết 3 câu: Proxy khác Decorator ở điểm nào, khi cả hai đều bọc cùng một giao diện.

### ✅ Tiêu chí hoàn thành

- [ ] Monitor chạy được với cả máy thật và stub, và xử lý được lỗi mạng.
- [ ] Virtual proxy chỉ tải ảnh khi cần, và không chặn luồng chính.
- [ ] Caching proxy được test bằng đồng hồ giả.
- [ ] Phân biệt được Proxy, Decorator và Adapter dựa trên mục đích.
